# Architecture

## Shared Desktop presentation and online demo

`packages/timeline/src/desktop` owns the browser-safe Desktop composition (`DesktopExplorer`), neutral theme/styles, date picker, navigation, appearance preferences/settings, Chinese catalog and Radix track-header menu. The native host and Web `/timeline` consume this same implementation. Desktop's old presentation paths re-export the shared modules; its collectors, Tauri commands, archive adapters, diagnostics and application-icon reads stay in `apps/desktop`. The main Timeline entry remains independent of these optional Desktop widgets; consumers opt into `@tracel/timeline/desktop` and its CSS. The existing Radix/DayPicker dependencies are declared by the shared package without introducing new versions.

Web `DemoApp` injects a `DataProvider`; the default `@tracel/timeline/desktop-demo` generates deterministic, explicitly fabricated CPU-frequency, GPU/engine/VRAM, battery/power and microphone samples on the original seven-day activity capture. Missing readings remain missing, and zero readings remain zero. The data source never enters native collector queries or real persisted history. Timeline shows input audio when present and replaces the legacy aggregate GPU lane when adapter tracks are supplied. Provider-supplied initial ranges are honored after asynchronous loading.

Online collection switches only simulate checkbox state and never start monitoring or remove historical examples. The menu explains this distinction. Web enables Timeline and appearance Settings navigation; native diagnostics/tools are omitted. Web appearance uses a separate localStorage key and mounts on the client to avoid saved-language/zoom hydration mismatches. Demo host viewport styles are gated by `.desktop-ui`; the theme effect restores document variables/language on unmount. The product page and Radar retain their independent layout and scrolling. Earlier descriptions of Web retaining legacy styling refer to the pre-website-demo implementation.

## Application icons

Desktop's Range Overview application list supplies an optional icon-renderer slot to the shared Explorer; Web keeps its existing fallbacks. The native Capture adapter retains `Application.executablePath` independently of the tooltip's short `exe` name. Exact-path category rules also use this full source path. No database schema change is needed.

The `application_icon` IPC reads local absolute EXE paths on a blocking worker, extracts the first resource with Windows `ExtractIconExW`, renders 32×32 pixels with GDI and encodes PNG. Two background passes preserve modern alpha and legacy mask transparency. RAII releases the icon, bitmap and drawing context; no executable is launched or Shell extension invoked. Missing/protected/uninstalled/iconless apps fall back to the existing generic glyph. PNG encoding reuses the already locked `png 0.17.16` crate as a runtime dependency; no new package version, driver, icon pack or external runtime is added. Release-size impact has not been measured.

PNG files live under `app_local_data_dir/icon-cache`, beside `activity.sqlite3`, rather than inside SQLite. A versioned hash of normalized executable path, file size and modification timestamp selects the cache entry. Corrupt/oversized entries are regenerated, cache write failures still return extracted icons, and pruning keeps at most 512 owned PNG files by creation/write age. The cache may be deleted while the client is closed; icons are regenerated on later requests. It stores no activity history. Updating an EXE invalidates its native cache key on the next request; the frontend shares successful and failed requests during the current session, so a restart refreshes already displayed icons.

Frontend icon requests are deduplicated by path, bounded to 256 remembered promises and limited to four concurrent IPC calls. Collector polling does not reread icons. Each mounted image owns and releases its Blob URL; failed reads/decodes keep the fallback. The existing `img-src blob:` policy suffices, with no new filesystem capability or broad file-serving scope. Native extraction/cache behavior is tested against a copied Windows executable; browser integration uses mocked IPC.

## Editable application categories

Desktop creates `categories.json` in Tauri's app config directory on first read; existing files are never overwritten. The default JSON ships with the shared Timeline package and contains a single category tree and exact executable rules, using snake_case keys (`parent_id`, `category_id`) with no compatibility for the initial camelCase draft. Native IPC reads at most 1 MiB on a blocking worker; the shared parser rejects cycles, missing references, duplicate identities/rules and invalid colors. Desktop reloads on window focus, retains the last valid in-memory configuration on errors, and exposes the actual path and config-folder shortcut in Settings. There is no category editor or tags system yet.

Classification is derived at display/query time, not written into SQLite observations. Case-insensitive normalized full paths override basename rules; unmatched applications remain Uncategorized. Rules currently apply to executables only, not titles/URLs. Each application receives one category. Range Overview adds an Apps/Categories switch with AFK-excluded active time; parents include descendant totals and must not be added to their children. Category rows show both a percentage and a horizontal bar using total selected active time as the common denominator. Display optionally colors app lanes by category (inheriting the nearest ancestor color); defaults retain application colors. Editing the JSON reclassifies historical views without rewriting the archive. The standalone Web demo remains unchanged; the Desktop browser preview uses the same default JSON.

## Implemented

Web `/` is a Chinese static product page with locally hosted, versioned Desktop downloads and real Desktop screenshots using fabricated example data. `src/release.json` owns public release metadata; Web tests verify the EXE size, SHA-256, checksum file and PE signature. `/radar` preserves the original Radar experience and `/timeline` preserves the interactive Activity demo. MapLibre and legacy live/industrial styles are imported by the demo route layouts instead of the root layout; the landing page uses a scoped CSS module and no product-specific client state. Desktop and the reusable Timeline package are unaffected by website routing.

The root is an npm and Cargo workspace. `apps/web` owns Next.js routes, Radar, MapLibre/Three.js, Tailwind and static Cloudflare export. `apps/desktop` owns a lean Vite/React entry point and Tauri 2 lifecycle; it imports neither Radar nor Next.js.

Web and browser preview pass `@tracel/timeline/mock` to `Explorer` from `packages/timeline`. Native Desktop supplies a controlled Capture derived from persisted numeric samples and state intervals; it never substitutes demo readings for missing measurements. This preserves the original Canvas Timeline, selection/analytics, hover/context, collapse/resize, settings and export. The package owns React UI, domain helpers and scoped CSS. Host resets remain in each app. No native API appears in the package or Web bundle. Pure model/analytics and mock subpath exports avoid mixing the demo adapter into the main UI entry point.

`tracel-core` defines UTC millisecond ranges, subjects, metrics, observation quality and the serialized system/media/activity observation DTOs. `tracel-storage` implements SQLite with rusqlite and a statically bundled SQLite engine, transactional migrations, WAL, FULL synchronization and atomic writes. `tracel-query` implements clipped weighted gauge means and rejects byte counters. `tracel-agent` provides a platform-neutral sampler with selective Windows CPU/RAM/network/disk/audio/media and foreground/window/desktop application/idle readers, a one-time foreground reader and a one-shot CLI.

Tauri owns one collector worker, configuration persistence, a SQLite writer and a bounded 1,800-observation memory ring restored from the database at startup. A condition variable suspends the worker when collection and power requests are idle. Desktop-specific IPC exposes configuration, status, history, foreground diagnostics and power tools. Settings, Utilities, Audio and System metrics occupy host-provided pages in the shared shell; the native Timeline displays recorded CPU, RAM, network, disk, audio and estimated media intervals. Opt-in foreground/window, desktop app presence and AFK tracks show real archived intervals; uncollected activity stays blank. Opt-in GPU utilization/engine/VRAM, battery/power state and Windows-reported CPU frequency are collected through system APIs. GPU tracks are per adapter and expandable into engine tracks; frequency sits directly below CPU with a separate GHz axis. Unsupported or historical missing hardware measurements stay blank. The UI polls status every two seconds and reads bounded history only on the metrics page. Native save-dialog/filesystem plugins export JSON to a user-selected path; window-state restores placement.

Prevent automatic sleep is set and cleared on the collector thread, requesting system activity only and allowing display timeout. Closing the client joins that worker and releases its power request. Collection preferences persist, but sleep prevention is always off at startup. Manual display-off is disabled in both UI and native IPC after a wake-up reliability incident; no monitor command or delayed display task remains. Browser preview disables native features. No collection APIs enter the shared package or Web.

Tauri is an explicit root Cargo member sharing lockfile and target directory. Default Cargo members are the four foundation crates; --workspace adds Tauri SDK dependencies. Native builds default to an EXE without installer packaging. An optional portable ZIP command and explicit NSIS installer command are available; see apps/desktop/README.md for validation limits.

Desktop owns its fixed navigation, viewport sizing and local appearance preferences. Shared Explorer exposes optional header variants and a navigation slot; Web retains its existing default shell. All Desktop pages omit the global header. Timeline uses the optional compact, toolbar-first content layout, with export and shortcuts in its toolbar and a demo label in its overview. Desktop uses neutral design tokens, validated/persisted custom accents, system fonts and owned shadcn-style components backed by Radix and React DayPicker. Shared Explorer exposes a date-picker render slot and Canvas palette, so these UI dependencies stay in Desktop. A flex-based Timeline content pane fills the viewport and anchors its footer. Pending native settings saves guard repeat mutations without dimming the entire settings page; Web retains its existing visual styling. Navigation supports pointer/keyboard resizing and persists its preferred width. Interface zoom scales the host without changing timeline time ranges; Canvas uses measured bounds to convert screen coordinates to logical track coordinates and to size its backing buffer.

Desktop owns the persisted English/Chinese preference and provides its message catalog to a lightweight shared Timeline locale context. The default context is English, keeping Web unchanged; locale changes update labels and Canvas date/duration formatting without changing data, identifiers or view state. Native diagnostics and export data remain unmodified. Desktop buttons use an owned ghost/secondary primitive and shared focus tokens.

Utilities owns one-shot file usage UI. Its Desktop-native adapter queries Windows Restart Manager on a blocking worker, with RAII sessions and bounded buffer retries. It shares no file data with the Timeline or metrics history and adds no background watcher, driver or bundled runtime. Settings retains appearance/foreground diagnostics and links to Timeline collection controls; power controls move to Utilities while keeping the same collector-thread lifecycle.

## Explicit Windows utilities

Desktop Utilities owns Windows update-policy controls, environment discovery and a fixed allowlist of Windows settings shortcuts. Embedded PowerShell scripts use built-in Windows PowerShell with no profile, a hidden window, UTF-8 JSON, bounded output and a 12-second timeout on blocking IPC workers. No detected runtime executable is launched and no new package/runtime is bundled. Environment scans run on demand with an overlap guard. These diagnostics do not enter the collector or SQLite archive.

Automatic-update control uses the documented HKLM `WindowsUpdate\AU\NoAutoUpdate` DWORD on supported Pro/Enterprise/Education editions, requiring an already elevated client. It never requests elevation or applies settings on startup. A flushed single-value snapshot in HKLM `SOFTWARE\Tracel\UpdatePolicy` preserves the original absent/zero value before writing; the start timestamp is recorded after verification. Restore touches only the value Tracel changed and refuses conflicting external changes. A machine-wide mutex serializes mutations. Existing externally disabled policies are read-only; their start time is unknown. This reads a registry policy, not proof of effective Windows/MDM behavior. No service, scheduled task, ACL, update deadline or pending restart is changed. Indefinite means until restored or overridden, not a permanent guarantee. Year-based expiry is deferred because restoration while the app is closed needs an additional persistent mechanism.

## Future boundaries

Windows collectors belong to the interactive-user agent. Desktop queries SQLite on blocking IPC workers using independent read-only connections, timestamp/interval indexes, local-day bounds (up to 25 hours for DST) and incremental numeric row-ID cursors with refreshed interval sets. Queries fail explicitly above 50,000 observations or state intervals rather than silently truncating. The host converts only the requested day into the shared Capture model, retaining actual intervals, per-metric gaps and weighted coverage. Timeline supports one-hour/day views and live following, paused by manual navigation or selection. Cross-day LOD, rollups and retention controls are deferred; current history is not automatically deleted. DataProvider.load remains the demo API; the shared UI accepts an optional controlled Capture without native imports.

The agent must eventually outlive UI windows. Process supervision, autostart and shutdown strategy are deferred. Today's shell hosts the collector library in-process and stops collecting at exit; it does not launch an independent agent or Session 0 service.

Radar visitor models and Activity desktop models remain independent. TS/Rust semantic compatibility is documented without premature generated bindings.

The agent owns selective GetIfTable2, PDH, Core Audio and WinRT SMTC readers, with lazy resources confined to one collector thread. Native reads run outside the IPC state mutex; settings revisions discard stale in-flight observations. Desktop Utilities separately owns explicit AC/DC Windows display-timeout editing with conflict detection and best-effort rollback; no screen-off broadcast or sleep-plan edit is introduced.

## Audio diagnostics page

Desktop owns a separate on-demand Core Audio monitor, independent of the two-second telemetry collector. Its MTA worker is idle at startup, starts on the first Audio-page visit, keeps running across navigation/minimization, and releases COM/session resources on pause or exit. It samples cached session meters every 50 ms, refreshes active endpoints and defaults every second, and publishes snapshots to the UI every 500 ms. New-session notifications retain agile references in a bounded queue; the worker resolves them and owns the session list. Periodic enumeration supplements notifications, rather than trusting a single default-device snapshot. Endpoint/session limits are reported explicitly. Recent signal observations stay in bounded memory for 60 seconds, survive session exit, and are never persisted to SQLite. Paused results remain frozen until monitoring resumes.

Default input/output and communications devices are read through IMMDeviceEnumerator. A fixed ms-settings:sound action opens Windows settings for explicit user selection; the app does not use private IPolicyConfig interfaces, registry audio-policy writes or device overrides. Only existing windows/windows-core bindings and system DLLs are used; no new Cargo packages, driver or audio runtime are introduced.

## Normalized archive

Schema 4 stores metrics in system_samples and stores application/process/window/media entities separately from state intervals. tracel-storage owns atomic interval extension and queries because both depend on SQLite transaction boundaries; collectors continue to publish platform-neutral observations. Foreground focus and window titles have independent intervals, joined for Timeline. Process instances underpin Apps lifetimes without adding another UI track. Metadata is interned; sampling gaps and writer restart boundaries stay explicit. The old archive is converted transactionally without deleting history. See data-model.md for tables, continuity rules and migration limits. No background-title collector, LOD or automatic retention is added in this change.

Desktop supplies neutral Timeline label tokens (--tx-label-muted / --tx-label-text) and Canvas text/muted palette entries. Ordinary labels and action icons stay neutral when the accent changes; selection and semantic series keep their colors. Shared CSS retains the original Web colors as token fallbacks.

## Hardware metrics

Schema 5 adds nullable CPU-frequency MHz and variable per-adapter GPU/battery observation fields to system_samples without rewriting history or state intervals. The recent-ring view and incremental queries return the new fields. Desktop supplies optional metric track definitions and metadata to the shared timeline, keeping Windows APIs outside the shared package. Each adapter has utilization (expandable per physical engine) and dedicated/shared used-memory tracks. Battery percentage and nullable plugged-in/charging state get separate tracks. GHz is a separate row adjacent to CPU rather than a percentage overlay. Web/demo captures have no hardware track definitions and retain their existing layout. Sources remain independently selectable and default off on preference migration. No extra Cargo package or runtime is bundled.

## Input audio level

The collector has an independent opt-in microphone meter source using the existing Core Audio endpoint meter, defaulting off for old settings. It reads default multimedia input peak only, with no audio client or raw recording. Schema 6 persists nullable input levels. Native Timeline adds an input lane immediately above output, while the Web/demo layout stays unchanged. System metrics, settings and exports expose the input source independently; the separate Audio diagnostics worker is unchanged.

## Track collection context menu and GPU labels

Desktop owns a shadcn-style Radix Context Menu through the shared Explorer/Timeline renderTrackHeaders slot. Only the label column (including its axis and collapsed groups) triggers the menu; Web keeps its normal layout with no Radix/native dependencies. All source toggles and the master switch move from Settings into this menu, reusing the existing persisted settings mutation, busy guard and failure behavior. Settings links back to Timeline. Changes affect collection, not historical visibility or archive deletion. The menu supports keyboard context-menu invocation and viewport-bounded portals with the existing interface scale.

GPU PDH adapter IDs are normalized to lowercase for DXGI name lookup. Display adapters also normalize old casing without modifying archived JSON, prefer the latest resolved model name over fallback names, and give unresolved historical adapters short GPU-number labels. Different LUIDs/physical indices remain separate; devices from different Windows sessions are never guessed to be the same hardware.

## GPU display preferences

Desktop defaults to simplified GPU names (remove GeForce and a trailing Graphics/GPU, preserving manufacturer/model/Laptop) and hides adapters named Microsoft Basic Render Driver. Both preferences persist with appearance settings and are accessible under GPU display in the track-header context menu. They never change collection switches, archived names/measurements or raw exports. Filtering uses resolved full names per canonical identity across the loaded range, including older fallback-only rows, and applies to Timeline tracks, range analytics and System metrics cards. The overall displayed GPU summary excludes hidden adapters; enabling the software-adapter option restores them. Unresolved and other adapter names are retained rather than assuming they are software. Memory subtitles contain only the selected display name; axes/hover/export still carry GiB. Web/demo and native collector APIs are unchanged.
